# مهمة: بناء الهيكل الأساسي للمشروع — روشتة (Roshetta)

## 1. اختيار التقنيات (Stack)

نفس التقنيات المستخدمة في مشروع "تكنو صيانة" — إعادة استخدام خبرة مثبتة بدل تجربة تقنيات جديدة من الصفر:

| الطبقة | التقنية | السبب |
|---|---|---|
| Frontend + API | Next.js (App Router) | نفس نمط مشروع الصيانة، منشور على Vercel |
| قاعدة البيانات | PostgreSQL (Neon) | نفس المزود، دعم فروع (branching) مفيد للتطوير |
| ORM | Drizzle | نفس الأداة المستخدمة سابقًا |
| UI | Tailwind + shadcn/ui | متوافق مع نظام التصميم اللي بنيناه (RxTag، الألوان) |
| خدمة الواتساب | Node.js + Baileys، منشورة على Render | **إعادة استخدام مباشرة** لنفس الخدمة والبنية من مشروع الصيانة (جلسة محفوظة في Postgres) |
| خدمة الملاحظات الصوتية | Python + FastAPI + Whisper | تحتاج بيئة Python منفصلة، منشورة كخدمة مستقلة |

## 3. مخطط قاعدة البيانات (الجداول الأساسية)

```sql
-- العيادات والفروع
CREATE TABLE clinics (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  phone TEXT,
  address TEXT,
  created_at TIMESTAMP DEFAULT now()
);

-- المستخدمون (أطباء، استقبال، إدارة)
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  clinic_id UUID REFERENCES clinics(id),
  name TEXT NOT NULL,
  role TEXT NOT NULL, -- doctor | receptionist | admin
  phone TEXT UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT now()
);

-- المرضى
CREATE TABLE patients (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  clinic_id UUID REFERENCES clinics(id),
  name TEXT NOT NULL,
  phone TEXT NOT NULL,
  date_of_birth DATE,
  medical_history_summary TEXT,
  created_at TIMESTAMP DEFAULT now()
);

-- المواعيد
CREATE TABLE appointments (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  clinic_id UUID REFERENCES clinics(id),
  patient_id UUID REFERENCES patients(id),
  doctor_id UUID REFERENCES users(id),
  scheduled_at TIMESTAMP NOT NULL,
  status TEXT DEFAULT 'SCHEDULED', -- SCHEDULED | CONFIRMED | COMPLETED | NO_SHOW | CANCELLED
  noshow_risk TEXT,                -- LOW | MEDIUM | HIGH (من services/noshow)
  noshow_risk_is_heuristic BOOLEAN DEFAULT true, -- PLACEHOLDER LOGIC حتى نجمع بيانات كافية
  is_first_visit BOOLEAN DEFAULT false,
  created_at TIMESTAMP DEFAULT now()
);

-- الملاحظات الطبية / الروشتات
CREATE TABLE clinical_notes (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  appointment_id UUID REFERENCES appointments(id),
  rx_number TEXT UNIQUE NOT NULL,   -- يظهر عبر مكوّن RxTag
  chief_complaint TEXT,
  diagnosis TEXT,
  prescription TEXT,
  treatment_plan TEXT,
  is_ai_drafted BOOLEAN DEFAULT false,
  doctor_approved_at TIMESTAMP,     -- NULL يعني لسه مسودة، ميظهرش كملف نهائي
  created_at TIMESTAMP DEFAULT now()
);

-- موافقات التسجيل الصوتي (متطلب إلزامي من خطة الميزات)
CREATE TABLE recording_consents (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  appointment_id UUID REFERENCES appointments(id),
  consented_at TIMESTAMP NOT NULL,
  consented_by TEXT NOT NULL -- اسم/توقيع المريض أو ولي الأمر
);

-- الفواتير
CREATE TABLE invoices (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  appointment_id UUID REFERENCES appointments(id),
  amount NUMERIC NOT NULL,
  payment_method TEXT, -- CASH | CARD | MIXED
  paid_at TIMESTAMP,
  created_at TIMESTAMP DEFAULT now()
);

-- جلسة واتساب (نفس جدول مشروع الصيانة بالضبط)
CREATE TABLE whatsapp_auth_state (
  id TEXT PRIMARY KEY DEFAULT 'singleton',
  auth_data JSONB NOT NULL,
  updated_at TIMESTAMP DEFAULT now()
);
```

**ملاحظة إلزامية:** `clinical_notes.doctor_approved_at` لازم يكون `NULL` بشكل افتراضي دايمًا — أي كود بيعرض الملف الطبي للمريض أو بيطبعه لازم يتحقق إن الحقل ده مش فاضي، وإلا مسودة الـAI غير المراجَعة ممكن تتعرض كأنها ملف طبي معتمد.

## 4. ترتيب البناء (Build Order)

| المرحلة | المحتوى | يعتمد على |
|---|---|---|
| 1 | هيكل المشروع + قاعدة البيانات + المصادقة (Auth) | — |
| 2 | الحجز وملف المريض الأساسي (CRUD) | المرحلة 1 |
| 3 | نظام التصميم (RxTag، الألوان، اللوجو) — يُطبق من أول شاشة تُبنى، مش يُضاف لاحقًا | المرحلة 2 |
| 4 | الفواتير والمدفوعات | المرحلة 2 |
| 5 | خدمة الواتساب (نشر منفصل على Render) + تذكيرات المواعيد الأساسية | المرحلة 2 |
| 6 | منطق تقييم الغياب (Heuristic) + ربطه بتذكيرات واتساب الذكية | المرحلة 5 |
| 7 | خدمة الملاحظات الصوتية (Python + Whisper + Claude) — شاملة شاشة الموافقة الإلزامية | المرحلة 2 |

**لماذا نظام التصميم في المرحلة 3 مبكرًا:** بناء الشاشات الأساسية أول بتصميم افتراضي ثم "تجميل" لاحق بيؤدي غالبًا لعدم اتساق. الأفضل تطبيق `RxTag` والألوان من أول شاشة حجز تُبنى.

## نطاق العمل لهذه المهمة تحديدًا
- إنشاء هيكل المجلدات كاملًا
- إنشاء وتشغيل مخطط قاعدة البيانات (migration أولي)
- إعداد مشروعي الخدمات المنفصلة (whatsapp-service، clinical-notes-service) كمستودعات فارغة جاهزة للنشر، بدون منطق كامل بعد — هذا يأتي في المهام التالية لكل ميزة على حدة

## اختبار القبول
1. هيكل المجلدات مطابق للمخطط أعلاه
2. الجداول الأساسية منشأة في قاعدة البيانات وتظهر في أداة إدارة قاعدة البيانات
3. `clinical_notes.doctor_approved_at` قابل للتحقق أنه NULL افتراضيًا عبر اختبار إدخال بسيط
4. مشروعا الخدمات المنفصلة موجودان كمستودعين جاهزين للنشر على Render (حتى لو المنطق الداخلي فارغ حاليًا)
